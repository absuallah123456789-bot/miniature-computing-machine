# ChesLan — LAN chess (Tauri v2 + Rust)

Two devices on the same Wi-Fi/LAN find each other automatically and play full-rules chess **offline**. No internet servers.
Targets: Windows, Linux, Android (`com.malikhw47.cheslan`). Rules engine, networking and opening lookup are all Rust; the UI is plain HTML/JS (no bundler, no JS chess library).

> **Status:** written but **not compiled or run** (per the "do not build" instruction). Expect to fix a few compile errors on first `cargo test` / `tauri dev`. Please report/paste them and they're quick to fix.

## Piece images

A **placeholder set of original art (CC0)** is included in `ui/assets/pieces/` (`whitepawn.png` … `blackking.png`, 256×256 transparent PNG) so you can test right away. It's generated by `scripts/gen_pieces.py` (needs Pillow). To use your own, drop your PNGs over these files with the same names (`white|black` + `pawn|knight|bishop|rook|queen|king`). Different naming? Edit `pieceSrc()` at the top of `ui/js/app.js`.

## Run / build

Common: Rust (stable), Node 20+, then `npm install`. Icons are already generated in `src-tauri/icons` from a **placeholder** `assets/app-icon.png` (checkerboard — replace it and run `npm run icons`).

| Platform | Prerequisites | Dev | Release build |
|---|---|---|---|
| **Linux** | `libwebkit2gtk-4.1-dev build-essential libxdo-dev libssl-dev libayatana-appindicator3-dev librsvg2-dev` | `npm run dev` | `npm run build` → `target/release/bundle/{deb,rpm,appimage}` |
| **Windows** | MSVC Build Tools, WebView2 (preinstalled on Win 10/11) | `npm run dev` | `npm run build` → `target/release/bundle/{nsis,msi}` |
| **Android** | JDK 17, Android SDK + NDK 27, `NDK_HOME`/`ANDROID_HOME`, `rustup target add aarch64-linux-android armv7-linux-androideabi i686-linux-android x86_64-linux-android` | `npm run tauri -- android init && python3 scripts/patch_android.py && npm run tauri -- android dev` | `npm run tauri -- android build --apk --aab` |

**Tests (rules engine):** `cargo test -p cheslan-core --release` (or `npm test`). Covers perft on the five standard positions (start, Kiwipete, positions 3–5), castling rights/through-check, en passant (incl. horizontal pin), promotion, checkmate, stalemate, 50-move, threefold, insufficient material, SAN, PGN, ECO and transpositions.

Windows will show a firewall prompt on first run — allow **private networks**, otherwise peers can't connect.

## How playing works

1. First launch: username (empty ⇒ `user` + 8 random chars), profile picture → square 1:1 crop (drag + zoom slider) → saved into the app's local data dir as `avatar.png` (+ a 96 px JPEG thumbnail for the network). The original path is never referenced.
2. The LAN list shows avatar + name + OS of every ChesLan instance seen. Pick a **game settings** dropdown entry (bottom of the main screen, next to the small **Confirm** button), select a player and press **Confirm** to challenge them; an incoming challenge shows the time control and colours with Accept/Decline. No one visible? Use **Connect by IP**.
   * **Type:** No timer · Bullet (1 min, 1+1, 2+1) · Blitz (3 min, 3+2, 5 min) · Rapid (10 min, 10+5, 15+10) · Custom (Initial 1–120 min, Bonus 0–60 s sliders).
   * **Colors:** white pawn / black pawn / Random (your colour; the challenged side sees what they'll play before accepting). Settings are remembered.
   * **Clocks:** each side is authoritative for its own clock and reports it with every move; the increment is added after each move. Like lichess, clocks start once both players have made their first move. If your flag falls you send a `timeout`; if the opponent's falls and they never report it, you claim the win after a 2 s grace. Clocks pause while disconnected. Rematch keeps the settings and swaps colours.
3. Moves: **drag** a piece (it grows 10 % while held) or tap/click it and then a highlighted square. Pieces glide to their new square (castling slides the rook too; captured pieces fade). Promotion opens a picker with your piece images. The board flips automatically when you are Black. Previous/next controls review positions; moves are enabled again only at the latest position.
4. Gear: offer draw / resign / copy PGN. Chat button: overlay with bubbles (text only; max 500 chars; rendered via `textContent`, control chars stripped in Rust). A message of 1–4 emoji and nothing else is shown without a bubble at 120 % size.
5. Header subtitle = "by MalikHw47" until the first move, then the ECO opening name (hover for the ECO code).
6. End states: **check** = the king's whole square flickers red once per second; **checkmate** = the mated king's square is solid red (no flicker) + "GGs checkmate"/"GGs you lost"; draw/stalemate modals; timeout shows "GGs you won/lost". A lost connection opens the same popup with a **Connection Lost** reason. Buttons: **Rematch** (request → opponent accepts/declines; colours swap) · **Main screen** · **Game review** · **Keep board** (a persistent **Show popup** button reopens it).

## Networking (answers to Q3)

* **Discovery: UDP broadcast** on port `47474` (beacon JSON every 2 s to `255.255.255.255` and each interface's subnet broadcast; peers expire after 7 s). Chosen over mDNS because it needs no extra crates, works the same on all three OSes, and — important on Android — plain broadcast is delivered without holding a `MulticastLock` (multicast is what Android's Wi-Fi chipset filters). Avatars are too big for a datagram, so the beacon carries an avatar hash and the thumbnail is fetched once over TCP (`ProfileReq`).
* **Game channel: TCP** on port `47475` (falls back to a random port, advertised in the beacon). One connection per game. Frame = `u32 BE length` + JSON, max 256 KiB. Ping every 5 s; 15 s of silence or a closed socket ⇒ connection lost.
* **Auto-reconnect (10 polls, then give up).** The session gets an id (`sid`) in `accept`. When the link drops (and the opponent didn't deliberately `leave`), the side that originally dialled retries the TCP connection up to **10 times** (each try ≤2 s + 1 s pause) sending `resume{sid, moves, clock_ms}`; the other side waits and polls 10 times (3 s apart). The receiver validates the `sid`, reconciles move lists (a move lost in flight is replayed from the longer list; diverged histories abort), swaps clock values, answers `resume_ok`, and play continues. A banner shows "reconnecting (attempt n/10)…", then "Couldn't reconnect" after the 10th. Clocks are paused meanwhile. Limits: both apps must stay running, and the dialler's IP:port is the one used originally.
* **Android permissions** (added by `scripts/patch_android.py`): `INTERNET`, `ACCESS_NETWORK_STATE`, `ACCESS_WIFI_STATE`, `CHANGE_WIFI_MULTICAST_STATE`. Raw TCP/UDP sockets aren't subject to the WebView cleartext policy and need no runtime permission prompt. Some routers enable *AP/client isolation* (guest Wi-Fi) which blocks all LAN traffic — nothing an app can fix.
* **Messages** (`"t"` is the tag): `profile_req`, `profile{profile}`, `challenge{profile,v,tc,color}`, `accept{your_color,profile,tc,sid}`, `decline`, `busy`, `move{uci,ply,clock_ms}`, `timeout`, `resume{sid,moves,clock_ms}`, `resume_ok{moves,clock_ms}`, `chat{text}`, `draw_offer|draw_accept|draw_decline`, `resign`, `rematch_req|rematch_accept|rematch_decline`, `ping`, `leave`. Both sides run the full rules engine; an opponent move that is illegal, out of turn, or has the wrong `ply` closes the connection. Checkmate/stalemate/draws are derived locally from the same deterministic rules.

## Open questions

**1. ECO data.** Source: [lichess-org/chess-openings](https://github.com/lichess-org/chess-openings) (`a.tsv`…`e.tsv`), **CC0** public domain. Merged into `crates/cheslan-core/resources/eco.tsv`: 3,865 lines, ~395 KB, format `eco<TAB>name<TAB>pgn`. `include_str!` embeds it at compile time. At first use (warmed on a background thread at startup) each line is replayed with our own SAN parser and indexed by position key (placement+side+castling+effective ep), so **transpositions** resolve too. During a game the latest known position wins, so the name updates as theory deepens and sticks once you leave it ("Unlisted opening" if the first move isn't catalogued). Refresh by re-downloading the TSVs.

**2. Stockfish 19 Lite.** npm package `stockfish@19.0.1` (nmrugg/stockfish.js, GPL-3.0): `stockfish-19-lite-single.js` (28 KB) + `.wasm` (1.8 MB) are committed in `ui/vendor/stockfish/`. It runs as a **Web Worker inside the webview**, so there is nothing platform-specific to bundle — no native binaries or JNI tricks on Android. Single-threaded build ⇒ no cross-origin-isolation headers needed. Review: Rust provides FEN/UCI per ply (`get_review_input`); JS evaluates each position (`go depth 12 movetime 2500`), converts to win-% (`50+50·(2/(1+e^(−0.00368·cp))−1)`) and classifies by win-% lost: **Best** (engine move or ≤0.5) · **Excellent** <2 · **Good** <5 · **Inaccuracy** <10 · **Mistake** <20 · **Blunder** ≥20 · **Miss** (≥10 lost right after the opponent erred while you were clearly better) · **Brilliant** (a ≥2-pawn material sacrifice by static exchange that is still engine-best-ish, you aren't losing and weren't already crushing) · plus **Book** (position is in the ECO table) and an accuracy %. The table has the opponent on the left and **you always on the right**. The thresholds are my heuristics, not chess.com's proprietary ones.
*Licence consequence:* shipping Stockfish makes the distributed app GPL-3.0-compatible; this repo is GPL-3.0-or-later (`LICENSE`).

**3.** See *Networking* above.

**4. Cropping.** Custom ~100-line canvas cropper (`ui/js/crop.js`): fixed square frame, pointer-drag pan, wheel/slider zoom, no plugin or dependency, works on touch. Output: 256×256 PNG + 96×96 JPEG, validated by magic bytes and size in Rust before being written. The picker is a standard `<input type="file" accept="image/*">`.

## CI / releases / Android signing

The workflow (`.github/workflows/release.yml`) runs on push/PR to `main`/`master` and manually; it regenerates the Tauri icons from `assets/app-icon.png` before Android initialization and produces only the release APK and AAB; artifacts are uploaded; on `main`/`master` pushes an automatic `build-YYYYMMDD-HHMMSS` tag and GitHub Release with everything attached. Replace the documented placeholder `assets/app-icon.png` with the final artwork before release. Added for ChesLan: a rules-test job, Windows (NSIS + MSI) and Linux (deb, rpm, AppImage) desktop builds, Rust targets, `NDK_HOME` from the runner's preinstalled NDK and `tauri android init`.

* `ci.yml`: `cargo test -p cheslan-core` on every push/PR (no GTK needed thanks to the separate core crate).
* **Android signing — identical to vidasscreensaver:** repo secrets `KEYSTORE_BASE64`, `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD`. The job decodes the keystore to `$RUNNER_TEMP/release.keystore` and passes `KEYSTORE_FILE` etc. as env vars; `scripts/patch_android.py` injects a Gradle `signingConfigs.release` that reads them and **falls back to the debug key** when no keystore exists (set `REQUIRE_RELEASE_SIGNING=true` to fail instead). Create a keystore with `keytool -genkeypair -v -keystore release.keystore -alias cheslan -keyalg RSA -keysize 2048 -validity 10000`, then `base64 -w0 release.keystore` into the secret. Never commit it; keep a backup.
* `src-tauri/gen/android` is generated in CI (`tauri android init`), not committed — unlike vidasscreensaver, which is a native Gradle project. `patch_android.py` also adds the network permissions and fails loudly if a future Tauri template changes `build.gradle.kts`. The runner's preinstalled SDK/NDK are used as-is.

## Known limitations / honest notes

* Never compiled or run — see the status note. The Tauri/Android pieces (Gradle patch, SDK versions) are the likeliest to need tweaks.
* No sounds. Clock logic lives in the Tauri crate (not the core crate), so it has no unit tests yet.
* Draws are applied automatically at threefold repetition and at 100 half-moves (the 50-move rule is auto-claimed). Draw by agreement and resignation work via messages.
* LAN has no authentication: anyone on your network can challenge you (you must accept) — fine for casual play, don't treat it as secure.
